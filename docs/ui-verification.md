# UI verification

Two tools check the renderer, both local. **Fixtures** (`npm run fixtures`) render components on synthetic data in headless Chrome and compare them with the base commit. **App smoke** (`npm run smoke:app`) launches the real built app. How to use them is in `.claude/skills/visual-verify/SKILL.md`; this doc holds what was decided and why.

## Locked decisions

| Area                 | Decision                                                                                                                                                                              | Why                                                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What "changed" means | The current code against a re-render of the base commit on the same machine. No stored baselines, nothing to promote.                                                                 | A stored image goes stale, needs someone to accept it, and differs between machines. Two renders from one browser on one machine differ only when the code does.                 |
| Base commit          | The merge-base of `HEAD` and `main`, so uncommitted work on `main` compares with `HEAD`. `--base <ref>` overrides.                                                                    | It is the commit a reviewer compares the branch with.                                                                                                                            |
| Behaviours           | A behaviour is a sequence of `interact` steps in a whole-app fixture, ending on an `until` that passes or fails.                                                                      | It replaces the earlier rule that the renderer has no behavioural assertions. The states were already being driven; a step that can fail costs one more line.                    |
| States               | Every known state gets a fixture.                                                                                                                                                     | A state without a fixture is one nobody sees change.                                                                                                                             |
| Coverage             | A full check fails on a component file that no fixture imports, directly or through another component. Reaching it only through `App.tsx` does not count. `components/ui/` is exempt. | `App.tsx` imports every screen, so one whole-app fixture would otherwise cover everything and a new screen would never need its own. The shadcn files are vendored library code. |
| `pending.json`       | Lists the components still uncovered while the fixtures are being written. An entry that is covered or gone fails the check, so the list only shrinks. It is deleted when empty.      | The coverage rule could not be switched on with 59 components failing it.                                                                                                        |
| Unseen edits         | A full check warns when an edited source file is imported by fixtures and none of them rendered differently. A warning, not a failure.                                                | Most such edits are refactors. The ones that are not mean the state the edit changes has no fixture.                                                                             |
| Where it runs        | Locally only. CI runs neither the check nor the runner's tests.                                                                                                                       | The repository owner's decision (2026-11). Revisit if a UI regression ships that a full check would have caught.                                                                 |
| The real app         | `npm run smoke:app` is a separate command, required only when `src/main/`, `src/preload/` or `src/shared/` change.                                                                    | Fixtures replace all three with a fake. A renderer-only change cannot break them.                                                                                                |
| Finishing            | Shots are free while building; one clean full check finishes the work; three fix rounds at most.                                                                                      | A filtered check cannot report coverage or unseen edits, and a fourth round means the approach is wrong, not the pixels.                                                         |
| Variants             | Every fixture is shot at the default and the minimum window size, in light and dark. A fresh browser context per shot.                                                                | The minimum size and the second theme are where layouts break unnoticed. A context per shot means nothing one fixture stores reaches the next.                                   |
| Dependencies         | `playwright-core`, `vite`, `pixelmatch` and `pngjs`, all already installed. The browser is the machine's Chrome, then Edge, then Playwright's Chromium if present.                    | No browser download and no new package to audit.                                                                                                                                 |

## Invariants across files

- **`src/shared/api.ts` is the one description of `window.api`.** The preload's object `satisfies Api` and the fake in `src/renderer/src/fixtures/fake-api.ts` is typed as it, so adding a member breaks the typecheck until the fake has it too. The type catches a changed shape, not a changed meaning.
- **`fake-api.ts` is the gallery's first import.** App modules read `window.api` while they load (`OnboardingDialog.tsx` reads `window.api.platform` at module scope), so the platform comes from the URL, not from a fixture's `api`.
- **The gallery and the runner share a contract:** the URL parameters `id`, `theme` and `platform`; `window.mounted`, `window.fixtures`, `window.fixtureErrors`; the `window.fixtureInput(step)` binding and its step shapes; and the `data-fixture-frame` attribute. The base commit is rendered by its own gallery and the current runner, so a change to this contract makes one comparison report every fixture as new or failed. That is expected once.
- **A frame is measured, not configured.** For `sheet()` and `sidebar()` the gallery mounts the real `<App />`, finds the `[data-screen]` element inside or outside `<main>`, and renders the fixture at that rectangle inside boxless copies of its ancestors. It depends on `ScreenTransition` setting `data-screen` and on the sheet being the only `<main>`.
- **`src/shared/window-size.ts`** feeds both `BrowserWindow` and the gallery's two sizes.
- **Base shots are cached** in `.fixtures/base/` under the commit, the browser version, and a hash of `scripts/fixtures/render.mjs` and `package-lock.json`. Anything else that can change a render belongs in that key.

## Measured facts

- **Rendering is deterministic only with software GL** (2026-11-12, Chrome 157, macOS on an Apple GPU). On the hardware GPU, two renders of the same page differed by one to three levels at two anti-aliased icon pixels: one fixture split 13 to 27 over 40 renders, even one page at a time. `--disable-gpu`, `--disable-gpu-rasterization`, `--disable-partial-raster`, `--disable-lcd-text`, `--disable-composited-antialiasing`, `--num-raster-threads=1` and `--disable-skia-runtime-opts` did not fix it; `--use-angle=swiftshader` gave identical bytes on every repeat. The comparison therefore allows no tolerance.
- **Speed** (same date, 10-core Mac): 96 shots in about 30 s, 0.3 s each. Four browsers with one page each was fastest; more pages or more browsers were slower. The base commit costs the same again, once per commit. At that rate 210 fixtures take about four and a half minutes. Most of the time is page start-up: each shot is a fresh page loading about 150 unbundled modules from one Vite server.
- **The base commit renders from a git worktree inside the repository** (`.fixtures/worktree/`, removed after each use), so its imports resolve to this checkout's `node_modules`. Tailwind scans it correctly there: identical code rendered byte-identical from the worktree and the checkout.
- **Playwright does not report favicon requests**, but their 404 reaches the page's console. `fixtures.html` declares an empty icon for that reason.
- **A failed query retries three times over seven seconds** by default. The gallery's `QueryClient` sets `retryDelay: 0`; the retries still happen.

## Rejected alternatives

- **Vitest browser mode.** Needs a provider pinned to the exact Vitest version, the full `playwright` package and a browser download. `toMatchScreenshot` is experimental and fails a new screenshot's first run. `--changed` is unreliable with Tailwind, where every class lives in one stylesheet. It has an open Windows-only hang (vitest #10890).
- **Storybook.** Local visual diffing needs a cloud service.
- **Stored or committed baselines.** See "What 'changed' means".
- **A CI gate.** See "Where it runs".
- **A tolerance in the comparison.** It hides small real changes, such as a design token moving by two levels. Deterministic rendering made it unnecessary.
- **One page per browser, reloaded between shots.** Measured 2026-11-13: 96 shots took 79 s against 27 s with a fresh context each. The settle step ran to its 5 s limit on many shots; the cause was not pinned down. The bytes were identical in shuffled order, so nothing leaked between shots.
- **A synthetic-event fallback for `interact` in a plain browser.** It would be a second implementation of input that disagrees with the first on hover and focus. Under `serve` a fixture shows its state before `interact`.

## Known gaps

- **Not run on Windows.** The paths, the worktree handling and the Edge fallback are written for it and untested there.
- **Fixtures cannot show** scrollbars (headless Chrome hides them), the window frame, Windows font rendering, the Content-Security-Policy, or the production bundle. On Windows the usable area at minimum size is slightly smaller than 860×500 because of the native frame; only `smoke:app` run on Windows sees that.
- **The fake can drift in meaning.** Nothing checks that the synthetic data in `fixtures/data.ts` is data the main process could produce.
- **App smoke reads this machine's real `~/.claude`.** It says the app starts and its sections render here. It asserts nothing about how they look.
- **Speed.** See "Measured facts". Serving a pre-bundled gallery would cut page start-up; it was not built.
